# VisualEncounters — V2.1 Nebulous Liberations update

The **V2.1 format** tab now exports a **map-specific, self-contained deployment ZIP** rather than a generic `encounters.lua` plus the entire global `ezencounters.zip`.

Start with **[V21_EXPORT_GUIDE.md](V21_EXPORT_GUIDE.md)** for the complete authoring and installation workflow.

## What changed

- **Area name required.** Enter the exact Tiled map name; output uses `encounters/<MapName>.lua`.
- **Scoped battle ZIP generated in the browser.** The builder uses `mods/ezencounters-v21-base.zip`, copied from the repaired working DEBUGLIB package. Each export changes only its package name and `liberation_aliases` dependency list.
- **Preserved EZEncounters helpers.** The generated package retains the original `get_package_id(alias)` and `package_build()` implementation, preventing the empty-mob regression.
- **All three encounter categories.** Regular, special, and boss encounters export together, with shared unique name validation.
- **No battle rewards.** Entries export `no_battle_rewards = true`, and reward configuration is not part of the V2.1 schema. Panel/mission loot remains a separate Liberation feature.
- **Freedom Mission:** New entries default to 3 turns and disabled flip (the server enables it only for surrounded terrain). Explicitly disabled imported missions remain disabled.
- **Grid:** Enemy positions are always authored. Manual teams, terrain tiles, and obstacles are exported when manual field overrides are selected.
- **Enemy Templates:** Saved OW templates are packaged as complete Lua registration modules with a separate manual registration guide. Custom AI implementations and the existing template registry aren't overwritten.
- **Mod ZIPs:** Optional hosted character mods are copied into deployment paths. Missing/unmapped mods are listed, not invented.
- **Legacy format:** The legacy tab, its downloadable `ezencounters.zip`, and the original enemy grid remain available.

## Where to put the exported files

```text
server-root/
├── encounters/<MapName>.lua
├── areas/<MapName>.tmx  ← create/maintain in Tiled; not generated by this tool
├── assets/ezlibs-assets/ezencounters/ezencounters-liberation-<slug>.zip
└── scripts/ezlibs-custom/nebulous-liberations/liberations/enemies/template_<name>.lua
```

**Before deployment** inspect the generated `INSTALL_V21_MISSION.md` and `ENEMY_TEMPLATE_REGISTRATION.md`. The bundle never replaces your current mission map or template registry.

## Testing

- Offline JavaScript package regression: `node tests/v21-export.test.js`.
- Browser smoke: created and exported a new mission, imported the current `DEBUGLIB.lua` with its three categories, and exported it again. The resulting package retained all original ZIP members.
- Live ONB client/server testing remains required before treating any specific new mission as verified.
