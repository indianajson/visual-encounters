# Visual Encounters — Attack Workshop + Enemy Workshop

**Source baseline:** `VisualEncounters_V21_Updated_Full_Site_2026-11-21.zip` and `encounters_and_scripts(1).zip` (the latest server sources available to this build). The optimized production `instance.lua` from the later DEBUGLIB packet-silence repairs is **not** available as a full current server upload; this release therefore **does not install `instance.lua`**.

## Architecture

| Component | Defines | Installs to |
|---|---|---|
| **Attack Template Workshop** | Reusable attacks: phase shapes, animation/motion, SFX, contact handling, stopping/piercing, summons, and targeting | `scripts/ezlibs-custom/nebulous-liberations/liberations/attacks/custom_templates.lua` |
| **Enemy Template Workshop** | Enemy OW/battle HP defaults, sprites, movement policy, allowable panels, AI selection, default attacks, prefix animation names | `scripts/ezlibs-custom/nebulous-liberations/liberations/enemies/custom_templates.lua` plus individual `template_*.lua` |
| **V2.1 encounter editor** | Battle enemies, ranks, battle grid, positions and area-specific battle ZIP | `encounters/<BaseArea>.lua` + `assets/ezlibs-assets/ezencounters/<battle-package>.zip` |
| **Tiled** | Dark Hole, Bot Config, encounter links, panel placement, spawn configuration | `areas/<BaseArea>.tmx` (not generated by Workshops) |

**These are separate layers**. An OW attack template is not the same as a client-side battle mod attack. Server collision/effects do not force another player's BattleMod AI to face a particular direction.

## Installation order

1. Merge the complete server Lua files from the **Server Workshop Patch** with your current server source. Don't replace a newer production file without comparison. This patch does **not** contain a full `instance.lua` from the older archive.
2. Update the Visual Encounters website with **Modified Website Files** or the complete site ZIP. Publish through your existing workflow to refresh cache fingerprints.
3. In **Attack Template Workshop**, author/save your attack, then export the **Attack Workshop ZIP** to your server root. It installs the attack registry automatically. Keep all referenced image, animation and sound files under their authored `/server/assets/...` paths.
4. In **Enemy Template Workshop**, choose the registered attack (or enter a sequence of names), create the OW enemy, and export **all enemy templates ZIP**. Its auto-registration module installs separately. The individual Lua files remain included for readability.
5. Define your Bot Config `Spawns` reference and `OW Encounter Config` in Tiled; install the matching V2.1 battle mod ZIP. Restart the server.
6. For independent `battle_max_health` and `battle_starting_hp` to override OW HP at battle handoff, run the included **optional, conservative** `apply_current_instance_battle_hp.py --dry-run` and apply only if it recognizes your latest `instance.lua`. It makes a backup and refuses unknown layouts.

## Eight-direction state names

A template gives a **PREFIX** and the runtime constructs `${PREFIX}_${SUFFIX}`:

| Facing | Suffix | Example with `WAVE` |
|---|---|---|
| Up | `U` | `WAVE_U` |
| Down | `D` | `WAVE_D` |
| Left | `L` | `WAVE_L` |
| Right | `R` | `WAVE_R` |
| Up Left | `UL` | `WAVE_UL` |
| Up Right | `UR` | `WAVE_UR` |
| Down Left | `DL` | `WAVE_DL` |
| Down Right | `DR` | `WAVE_DR` |

Body idle uses `IDLE_*` and attacks may use `ATTACK_*`, or any authored prefix. An opted-in bot plays its idle prefix on spawn and after a phased attack. Existing custom AI retains its own animation behavior. A sprite must **actually define** the states for every enabled facing; many older assets define only the four diagonals. Set `allow_cardinal_directions=false` on attacks that use old diagonal-only art. `Net.animate_bot` does not report animation completion to the server: phase completion is approximated with the sum of `.animation` frame durations, or your explicit phase duration when the file cannot be read.

## Multi-phase attack example

Use the phase editor shape painter (0/1 matrix values) to create this attack:

| Phase | Shape | Animation prefix | Movement | Contact |
|---|---|---|---|---|
| 1 | `1` | `WAVE` | Animation change | Pierce |
| 2 | `1,1` | `WAVE` | Smooth motion | Pierce |
| 3 | `1,1,1` | `BURST` | Instant motion | Stops at contact |

`1 / 1 / 1` creates a three-tile **forward** line. `1,1,1` is a three-tile **lateral** width. The selection math supports even-width (two-cell) masks and the eight directions. Each phase's effect is a visual Net bot, not a Lua `Battle.Spell`.

For every phase you may specify an SFX event at **start, midpoint, end, or contact** and a contact sprite/animation. Sound paths use existing `Net.play_sound(area_id, path)` and asset provisioning. Different phases may use different effect resources. `movement_mode=instant` uses `Net.transfer_bot`; `smooth` uses existing bot-property keyframes. `wait_for_animation` bases its wait on authored frame durations when available.

A phase can `spawn_bot_template='SomeRegisteredEnemy'`; it uses your real `Enemy.from` constructor and therefore inherits that bot's AI, HP display and asset provisioning. Spawns are capped (3 per phase / 12 active summoned bots per instance) to avoid network stalls.

### Persistent attacks: important limit

`linger_until_contact=true` holds the effect while checking collisions for up to `max_wait_seconds` (**8-second maximum**). This is deliberately *not* an unbounded across-turn hazard because one waiting enemy coroutine could block an entire mission turn and cause packet silence. A true persistent, independent area hazard requires a mission-tick lifecycle manager and should be merged against the latest production `instance.lua`.

### Contact and piercing

`pierce_players=true` lets a shape continue its phases after contacting a player. `pierce_players=false` stops the attack after its first valid contact. Per-phase overrides take precedence. `allow_repeat_hits=false` suppresses repeat damage to the same player across phases; it is not a universal battle-mod damage multiplier.

## Movement and territory

Enemy templates may set `move_range`, `movement_directions` (`any`, `axis`, `diagonal`, `none`), an optional panel-type allowlist, and `require_dark_panel_to_attack`. The allowlist controls movement; by default previous enemy-territory behavior is retained. Attack-only-on-Dark-Panel is enforced at the dispatch level, including old AI types. New movement limits also apply to the standard teleporter and smooth mover when configured; existing templates without those settings behave as before.

## What the existing attacks migration does

- Existing `attack_profile` data is registered under `Legacy_<EnemyTemplateName>` at server startup. No bespoke attack script is rewritten.
- The new Attack Workshop presents **16 source-grounded attack profiles and special-AI references**. `patterned_attack` profiles retain their original stage grammar; special AI entries are reference/selection entries only, not fake converted phases.
- For new custom phases, save under a new name with `runtime='phased_attack'`. Assign that name in Enemy Workshop. Export *both* registries and keep existing character mods/encounter definitions unchanged.

## Out-of-scope / verification

The website export is tested with Node.js; the server Lua modules and generated template files are syntax-tested, and 8-direction shapes, three-phase execution, SFX/contact and summoning were exercised in isolated Lua mocks. **Live ONB gameplay, animation playback, indefinite hazard lifecycle and newest runtime merge are not yet verified.** This avoids claiming workarounds for engine callbacks not present in source.

## Direction-state defaults and portable attack assignments (November 22 update)

The current Workshop controls and server runtime are documented in
[WORKSHOP_DIRECTION_AND_PORTABILITY_GUIDE.md](WORKSHOP_DIRECTION_AND_PORTABILITY_GUIDE.md).
By default, both bot and attack-effect animations use only the four diagonal
`PREFIX_UL`, `PREFIX_UR`, `PREFIX_DL`, and `PREFIX_DR` states. An explicit
**eight-direction animation** checkbox exists independently in each Workshop;
it changes animation suffix lookup only, not movement or attack targeting.

For portable authoring, export an Attack Workshop **JSON or ZIP** project and
import that into the Attack Workshop of another browser. Then assign the saved
attack in the Enemy Workshop. The Enemy Workshop's complete ZIP includes the
custom attack definitions referenced by its enemies in a separate
`attacks/enemy_workshop_templates.lua` registry. This registry does not overwrite
an independently installed `attacks/custom_templates.lua`.

Older saved enemy templates with attack-owned settings are migrated into named
attacks; bot animation prefixes are retained on the enemy.
